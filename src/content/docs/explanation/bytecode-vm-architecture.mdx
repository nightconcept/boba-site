## Why a Virtual Machine?

Boba uses a bytecode virtual machine (VM) architecture, sitting between interpreted and compiled languages. This design choice provides several key benefits:

### Compilation Speed
- **Fast development cycles**: Source compiles to bytecode quickly
- **No linking phase**: Bytecode is ready to execute immediately
- **Incremental compilation**: Only changed modules need recompilation

### Portability
- **Platform independence**: Bytecode runs on any system with the Boba VM
- **Consistent behavior**: Same code produces identical results everywhere
- **Single distribution**: One binary works across operating systems

### Optimization Opportunities
- **Bytecode-level optimizations**: Dead code elimination, constant folding
- **Runtime optimizations**: Hot path detection, inline caching
- **Memory efficiency**: Compact bytecode representation

## Compilation Pipeline

```
Source Code → Lexer → Parser → AST → Compiler → Bytecode → VM
```

### Lexical Analysis
The lexer breaks source code into tokens:

```boba
fn add(a: int, b: int): int { return a + b }
```

Becomes tokens:
```
[KEYWORD:fn] [IDENTIFIER:add] [LPAREN] [IDENTIFIER:a] [COLON] [TYPE:int] ...
```

### Parsing
The parser builds an Abstract Syntax Tree (AST) from tokens:

```
FunctionDeclaration {
    name: "add",
    parameters: [
        Parameter { name: "a", type: "int" },
        Parameter { name: "b", type: "int" }
    ],
    return_type: "int",
    body: ReturnStatement {
        expression: BinaryExpression {
            left: Identifier("a"),
            operator: Plus,
            right: Identifier("b")
        }
    }
}
```

### Bytecode Generation
The compiler translates the AST into bytecode instructions:

```
LOAD_LOCAL 0    ; Load parameter 'a'
LOAD_LOCAL 1    ; Load parameter 'b'  
ADD_INT         ; Add two integers
RETURN          ; Return top of stack
```

## Stack-Based Execution

Boba's VM uses a stack-based architecture for simplicity and efficiency:

### Instruction Execution
```boba
let result = (5 + 3) * 2
```

Generates bytecode:
```
LOAD_CONST 5    ; Stack: [5]
LOAD_CONST 3    ; Stack: [5, 3]
ADD_INT         ; Stack: [8]
LOAD_CONST 2    ; Stack: [8, 2]
MUL_INT         ; Stack: [16]
STORE_LOCAL 0   ; Stack: [], result = 16
```

### Benefits of Stack Architecture
- **Simple instruction set**: Most operations just manipulate the stack
- **Easy code generation**: Compiler emits straightforward linear bytecode
- **Compact representation**: Instructions are small and regular
- **Efficient execution**: Stack operations are fast and cache-friendly

## Memory Management

### Garbage Collection
Boba uses a generational garbage collector:

```
Young Generation: [newly allocated objects]
     ↓ (survival)
Old Generation: [long-lived objects]
```

**Generational Hypothesis**: Most objects die young, so focus collection on new objects.

### Object Layout
Objects are laid out efficiently in memory:

```rust
struct BobaObject {
    header: ObjectHeader,    // Type info, GC flags
    fields: [Value],         // Object data
}
```

### Reference Counting + Tracing
Hybrid approach for optimal performance:
- **Reference counting**: Immediate cleanup of acyclic structures
- **Cycle detection**: Tracing GC handles circular references
- **Incremental**: Small pause times for better responsiveness

## Instruction Set Design

### Core Instruction Categories

**Stack Operations**:
```
LOAD_CONST <index>     ; Push constant onto stack
LOAD_LOCAL <slot>      ; Push local variable
STORE_LOCAL <slot>     ; Pop and store in local slot
```

**Arithmetic**:
```
ADD_INT, SUB_INT, MUL_INT, DIV_INT    ; Integer operations
ADD_FLOAT, SUB_FLOAT, MUL_FLOAT       ; Floating point operations
```

**Control Flow**:
```
JUMP <offset>          ; Unconditional jump
JUMP_IF_FALSE <offset> ; Conditional jump
CALL <arg_count>       ; Function call
RETURN                 ; Return from function
```

**Object Operations**:
```
NEW_OBJECT <type>      ; Create new object
GET_FIELD <field>      ; Access object field
SET_FIELD <field>      ; Set object field
```

## Performance Characteristics

### Execution Speed
- **Bytecode dispatch**: ~10-50ns per instruction
- **Function calls**: ~100ns overhead
- **Object allocation**: ~50ns for small objects

### Memory Usage
- **Bytecode size**: ~30-50% of source code size
- **Runtime overhead**: ~8 bytes per object header
- **Stack frames**: ~40 bytes + locals

### Startup Time
- **Module loading**: ~1ms per 1000 lines of code
- **Bytecode verification**: ~0.5ms per 1000 instructions
- **VM initialization**: ~5ms total
